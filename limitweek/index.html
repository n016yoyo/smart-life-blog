제가 본 것

리셋 직전에 claude -p "/usage" 를 돌렸어요. 최근 7일 요청 19,483건, 세션 101개. 한도 사용량의 96%가 8시간 넘게 열려 있던 세션에서, 93%가 대화가 15만 토큰을 넘은 구간에서, 84%가 서브에이전트를 많이 쓴 세션에서 나왔어요. 화면 설명대로 독립적인 특성이라 합이 100%가 아니에요. 서로 겹쳐서 더하면 안 돼요.

※ 2026-10-20, 제 컴퓨터 한 대의 값이에요. 다른 기기와 claude.ai 는 포함되지 않아요(화면 설명).

왜 그럴까 (공식 문서)

공식 문서(code.claude.com/docs/en/costs, 「Long context」)에 따르면, 클로드 코드는 요청마다 대화 전체를 보내고 도구를 쓸 때마다 그 결과를 실은 요청을 또 보내요. 캐시 덕에 싼 값으로 다시 읽지만, 몇 시간 열어 둔 세션은 짧은 질문 하나도 사용량이 커요. 쉬는 시간이 캐시 수명보다 길면 첫 메시지는 캐시를 놓치고 전체를 다시 처리해요.

1

먼저 내 숫자 보기

터미널에서 claude -p "/usage". 클로드 코드 안에서는 /usage.

2

다른 일 시작할 땐 대화 비우기

/clear 로 대화를 비우고 새로 시작해요.

3

세션을 하루 넘게 방치하지 않기

열어 둔 세션이 길수록 매 요청에 실리는 대화가 길어져요.

내 숫자 보는 명령
claude -p "/usage"

아래는 내 `claude -p "/usage"` 출력이야. 세 비율(8시간 넘는 세션, 15만 토큰 넘는 구간, 서브에이전트 많은 세션)이 각각 얼마인지, 서로 겹친다는 점을 지키며 가장 큰 것이 무엇인지만 알려 줘. 원인은 추측하지 말고 출력에 적힌 것만 말해 줘.

이 방법의 한계예요

위 세 가지를 하면 한도를 얼마나 아끼는지는 재 보지 않았어요. 상관을 본 것이고 인과가 아니에요. 제 한도 소진에는 이 릴스를 만든 세션들도 들어 있어요. 숫자는 제 컴퓨터 한 대, 한 주의 값이에요.

영상의 터미널 화면은 실제로 돌린 명령의 저장된 출력이에요. 프로젝트·폴더 이름과 대화 내용은 싣지 않았어요. 장면 그래픽은 AI가 코드로 그린 그림이에요.
