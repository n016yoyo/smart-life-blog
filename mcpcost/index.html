어디서 시작된 얘기냐면

도구(MCP)를 많이 붙일수록 한도가 닳는다는 얘기를 자주 봤어요. 그래서 같은 요청 한 줄(「안녕이라고만 답해」)을 도구 0개와 200개로 보내 총 입력 토큰을 쟀습니다. 공식 문서(code.claude.com/docs/en/mcp)대로 도구 검색이 기본으로 켜져 있으면 도구 이름만 먼저 보여 주고, 끄면 정의 전체가 실려요.

※ 2026-10-20 내 컴퓨터의 값이고, 도구는 설명이 짧은 가짜(더미) 서버로 만들었어요. 한도 퍼센트는 재지 않았고 입력 토큰만 말합니다.

잰 값

도구 정의 크기는 전부 같고, 달라진 건 개수 하나입니다

조건도구 0개도구 200개늘어난 양
기본(도구 검색 켜짐)25,63328,233+2,600 (기준선의 약 10%)
도구 검색 끔41,11979,919+38,800 (기준선의 약 94%)

총 입력 토큰 = input + cache_creation + cache_read 세 값의 합. 같은 조건을 3번 재서 총합이 같았어요. 두 조건의 기준선이 달라서(내장 도구 정의까지 실려서) 항상 「각 조건에서 늘어난 양」으로 비교합니다. 도구 하나당 13토큰 대 194토큰이에요.

이 실험의 한계예요

더미 도구는 설명이 짧아요(도구당 약 190토큰). 실제 서비스 도구는 더 길 수 있습니다. 도구를 실제로 부른 요청, 한도 퍼센트, 다른 버전은 재지 않았어요. 제 Claude Code 버전 한 곳의 값이에요.

따라 하는 법, 하나 둘 셋

  1. 하나. 폴더 하나에 아래 두 파일 count.sh, dummy_mcp.js 를 같은 폴더에 저장하세요(chmod +x count.sh).
  2. 둘. ./count.sh 0 과 ./count.sh 200 을 실행하세요. 도구 검색을 끄고 재려면 ENABLE_TOOL_SEARCH=false ./count.sh 200.
  3. 셋. 두 값의 차이가 내 환경에서 도구 200개가 더하는 양이에요. 폴더에 CLAUDE.md 가 있으면 기준선이 달라지니 비교는 같은 폴더에서만 하세요.
측정 스크립트 (count.sh)
#!/bin/bash
# 사용: ./count.sh <도구 개수>   (도구 검색 끄기: ENABLE_TOOL_SEARCH=false ./count.sh 200)
# 같은 요청을 한 번 보내고 총 입력 토큰(input + cache_creation + cache_read)을 출력한다.
N=${1:-0}
D="$(cd "$(dirname "$0")" && pwd)"
CFG="$(mktemp)"
echo "{\"mcpServers\":{\"dummy\":{\"command\":\"node\",\"args\":[\"$D/dummy_mcp.js\"],\"env\":{\"N\":\"$N\"}}}}" > "$CFG"
claude -p "안녕이라고만 답해" --mcp-config "$CFG" --strict-mcp-config --output-format json < /dev/null \
 \
 | python3 -c "import json,sys; u=json.load(sys.stdin)['usage']; t=u['input_tokens']+u['cache_creation_input_tokens']+u['cache_read_input_tokens']; sys.exit('실패: 응답 없음(로그인 확인)') if t==0 else None; print(format(u['input_tokens']+u['cache_creation_input_tokens']+u['cache_read_input_tokens'],','))" \
 | sed "s/^/도구 ${N}개  총 입력 토큰 /"
rm -f "$CFG"
더미 도구 서버 (dummy_mcp.js)
#!/usr/bin/env node
// reel_mcpcost 더미 MCP 서버. 도구 N개(환경변수 N), 정의 크기는 전부 같다(비교 변수는 개수 하나).
const N = parseInt(process.env.N || "0", 10);
const tools = [];
for (let i = 1; i <= N; i++) {
  tools.push({
    name: `tool_${String(i).padStart(3, "0")}`,
    description: "Look up one record by its identifier and return the stored fields. Use when the user asks for the details of a single item in the connected system.",
    inputSchema: {
      type: "object",
      properties: {
        id: { type: "string", description: "Identifier of the record to look up." },
        fields: { type: "array", items: { type: "string" }, description: "Optional list of field names to return." },
        limit: { type: "integer", description: "Maximum number of rows to return." },
      },
      required: ["id"],
    },
  });
}
let buf = "";
process.stdin.on("data", (d) => {
  buf += d;
  let i;
  while ((i = buf.indexOf("\n")) >= 0) {
    const line = buf.slice(0, i).trim(); buf = buf.slice(i + 1);
    if (!line) continue;
    let m; try { m = JSON.parse(line); } catch { continue; }
    const send = (r) => process.stdout.write(JSON.stringify({ jsonrpc: "2.0", id: m.id, result: r }) + "\n");
    if (m.method === "initialize") send({ protocolVersion: m.params?.protocolVersion || "2024-11-05", capabilities: { tools: {} }, serverInfo: { name: "dummy", version: "1.0.0" } });
    else if (m.method === "tools/list") send({ tools });
    else if (m.method === "tools/call") send({ content: [{ type: "text", text: "ok" }] });
    else if (m.id !== undefined) process.stdout.write(JSON.stringify({ jsonrpc: "2.0", id: m.id, result: {} }) + "\n");
  }
});
