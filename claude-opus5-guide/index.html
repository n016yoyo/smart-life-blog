DELETE

이제 지워도 되는 옛 규칙 5가지

공식 문서가 "더 이상 필요 없다"고 명시한 항목들입니다. 설정 파일에 있으면 오히려 성능을 깎습니다.

지울 것왜
주석 제약"주석 쓰지 마라", "여러 줄 docstring 금지" 같은 명시적 금지

HOW

내 설정부터 진단하기

Anthropic이 공식으로 권하는 방법입니다. Claude Code에서 그냥 이렇게 치면 됩니다.

Claude Code에 입력
/doctor

내 CLAUDE.md가 몇 바이트인지, 스킬·플러그인이 컨텍스트를 얼마나 먹는지 숫자로 나옵니다. 그다음 이 프롬프트로 정리하세요.

진단 결과를 붙여넣고 함께 요청
위 /doctor 결과를 보고 내 설정을 Opus 5에 맞게 정리해줘.

정리 기준
1) 지울 것 = 공식이 "이제 불필요"라고 한 것
   - 주석 관련 명시적 제약
   - 사용 예시 나열
   - 정보 사전 로딩 지시
   - 시스템 프롬프트와 중복되는 반복 지시
2) 남길 것 = 코드가 자동으로 잡아주지 못하는 것
   - 내 취향·브랜드 규칙
   - 이 코드베이스만의 함정
   - 사실 정확성에 관한 규칙
   - 작업 순서
3) 안 쓰는 플러그인·스킬은 비활성화(삭제 말고 비활성화)

각 항목마다 "왜 지우는지 / 왜 남기는지" 한 줄씩 근거를 달아줘.
지우기 전에 목록을 먼저 보여주고 내 확인을 받아.
KEEP

지우면 안 되는 것

공식 권고는 "CLAUDE.md는 가볍게, 토큰 대부분은 코드베이스 함정에 쓰라"입니다. 기준은 하나입니다.

코드가 자동으로 막아주는 규칙은 문서에서 빼고, 코드가 구조적으로 못 잡는 것만 남긴다.
남길 것예
취향·브랜드 일관성"이 톤은 쓰지 않는다", "이 스타일로 고정"
이 프로젝트만의 함정"이 API는 이렇게 부르면 조용히 실패한다"
사실 정확성 규칙"숫자는 원본에서 확인하고 쓴다"
작업 순서"A를 끝내기 전에 B로 넘어가지 않는다"

반대로 테스트·린터·검증 스크립트가 이미 막아주는 규칙은 문서에서 빼도 됩니다. 어차피 어기면 코드가 거부하고, 그 메시지에 이유와 수정법이 다 들어 있습니다.

EFFORT

effort는 어디에 둘까

공식 가이드 기준입니다. 코딩·에이전트 작업이면 xhigh가 권장 시작점입니다.

상황권장
코딩·에이전트 작업xhigh (권장 시작점)
가장 어려운 문제max
단순·반복 작업low ~ medium
한 가지 주의. effort를 낮춰도 응답 길이는 안 줄어듭니다. 줄어드는 건 생각하는 양입니다. 답변이 길어서 불편하면 effort가 아니라 "짧게 답해달라"고 직접 말해야 합니다.
CASE

우리는 뭘 바꿨고, 얼마나 줄었나

말로만 하면 믿기 어려우니 저희 실측치를 공개합니다.

바꾼 것결과
CLAUDE.md 다이어트12,962B → 9,245B (-30%). 검증 스크립트가 이미 막아주는 12건을 짧은 포인터로 축약, 코드가 못 잡는 14건은 전부 유지
안 쓰는 플러그인 비활성화스킬 목록 9,048 → 2,245 토큰. 사용 이력 0회인 9개 팩
effort 재보정xhigh로 고정
응답 길이 지침 추가"기본 응답이 길고 effort로 안 줄어드니 의식적으로 짧게"
핵심은 "뭘 지웠나"가 아니라 "왜 남겼나"입니다. 지운 12건은 전부 어기면 코드가 거부하는 규칙이었고, 남긴 14건은 코드가 구조적으로 못 잡는 것들이었습니다.
