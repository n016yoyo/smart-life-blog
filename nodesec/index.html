제가 해 본 것

클로드에게 읽기 도구와 버전 확인 명령 세 개만 허용하고 점검을 시켰어요. 최신보다 낮은 항목은 10개(Node 1 · npm 전역 2 · pip 7). 그중 보안 공지가 걸린 건 Node 하나였고, 제 v22.23.2 는 2026-10-21 공식 공지의 22.x 수정 버전 v22.23.4 보다 두 단계 낮았어요. 공지에는 압축(Brotli) 해제 결함으로 원격 코드 실행이 가능하다고 적혀 있어요. 아무것도 설치하거나 바꾸지 않았어요.

※ 2026-10-25, 제 맥 한 대의 값이에요. 공지 본문은 nodejs.org 공식 페이지를 텍스트로 저장해 폴더에 넣어 두고 읽게 했어요.

1

공지 본문을 파일로 저장

nodejs.org 보안 공지 페이지 본문을 복사해 node_advisory.txt 로 저장하고, 그 폴더에서 실행해요.

2

읽기만 허용하고 실행

아래 명령처럼 --allowedTools 에 읽기와 버전 확인 명령만 넣어요. 설치·변경은 시키지 않아요.

3

공지 걸린 것만 먼저

나머지는 메이저 버전이 크게 바뀌는 것도 있어서, 호환을 확인하고 천천히 올려요.

점검 요청문 (제가 쓴 그대로, 파일 이름만 일반화)
내 컴퓨터를 점검만 해줘. 아무것도 설치하거나 바꾸지 말고 읽기만 해.
1) node -v, npm outdated -g, python3 -m pip list --outdated 를 실행해서 최신보다 낮은 항목을 전부 세어줘(Node 1개로 세고, npm 전역·pip 는 표에 나온 줄 수).
2) 이 폴더의 node_advisory.txt 는 Node.js 공식 보안 공지야. 내 Node 가 공지의 수정 버전보다 낮은지 알려줘.
3) 결과를 이 순서로 짧게: 낡은 항목 총 몇 개(종류별 개수), 그중 보안 공지가 걸린 건 몇 개, 급한 건 무엇이고 나머지는 서두를 필요가 있는지.
실행 명령 (요청문을 req_audit.txt 로 저장한 폴더에서)
claude -p "$(cat req_audit.txt)" --allowedTools "Read,Bash(node -v),Bash(npm outdated -g),Bash(python3 -m pip list --outdated)"

낡은 항목10개
Node1 (v22.23.2)

보안 공지 걸림1 (Node)
공지 중 22.x 해당7건 (high 3 · medium 3 · low 1)

이 방법의 한계예요

이 공지 하나만 대조했어요. npm·pip 항목에 다른 보안 공지가 있는지는 확인하지 않았어요. 업데이트 방법(설치 방식마다 다름)은 직접 확인하고 올리세요. 클로드의 판단(「나머지는 급하지 않다」)은 이 공지 기준이에요.

영상의 터미널 화면은 실제로 돌린 명령의 출력이에요. 공지 페이지는 Node.js 공식 블로그(2026-10-21 보안 공지)를 그대로 찍었어요.
