WHAT

이게 뭔데?

네이버 블로그 서로이웃 신청을 대신 걸어주는 자동화입니다. 그런데 아무 데나 거는 게 아닙니다.

내 주제(AI·자동화·클로드)로 블로그 검색을 돌려 후보를 모으고, 세 겹으로 걸러 살아남은 곳에만 신청합니다. 신청 메시지도 제목 복붙이 아니라 그 블로그가 실제로 다룬 글을 짚어서 씁니다.

검색 28곳 → 최근 활동 9곳 → 최종 3곳
왜 좁히나? 네이버는 서로이웃 신청에 하루 한도가 있습니다. 휴면 블로그나 광고 계정에 걸면 그 한도가 그냥 날아갑니다. 좁히는 게 손해가 아니라, 좁혀야 한도가 남습니다.
HONEST

먼저, 정직하게 짚고 갑니다

⚠ 수락률은 아직 모릅니다

신청이 나간 것까지가 이 자동화의 일이고, 상대가 받아줄지는 그 사람 마음입니다. 저도 며칠 뒤에 결과를 봐야 압니다. "수락률 몇 퍼센트"라고 적힌 글은 일단 의심하세요.

⚠ 제 자동화도 아직 완벽하지 않습니다

본문 읽기가 실패하면 제목 기반으로 내려가는 예비 경로가 있는데, 그게 바로 "하지 말라"고 한 제목 복붙입니다. 실제로 하루 아홉 건 중 세 건이 그 경로로 나갔습니다. 이 글에도 그대로 적어둡니다.

⚠ 계정 책임은 본인에게 있습니다

속도를 올리면 그만큼 위험합니다. 아래 대기 시간 설정은 줄이지 마세요. 부계정으로 먼저 돌려보시길 권합니다.

WHY

한도가 진짜 문제입니다

서로이웃 자동화에서 사람들이 가장 많이 하는 실수는 일단 많이 거는 것입니다. 그런데 네이버는 신청 단계를 실제로 호출하는 순간 한도를 깎습니다.

그래서 이 자동화는 순서를 뒤집습니다. 한도를 안 쓰는 조회로 먼저 물어보고, 되는 곳에만 신청합니다.

단계하는 일한도
1. 검색니치 키워드로 블로그 검색, 후보 수집안 씀
2. RSS 확인최근 14일 활동 · 광고 문구 · 주제 반복 검사안 씀
3. 사전확인신청 폼이 열리는지만 확인안 씀
4. 신청메시지 붙여 실제 신청여기서 처음 씀
결과: 안 되는 곳에 헛되이 쓴 한도가 0건입니다. 3단계까지는 아무리 돌려도 한도가 안 깎이니까요.
PREP

준비물은 딱 두 개

1. Claude Code

새 컴퓨터에 이것만 깔려 있으면 됩니다. 설치법은 클로드 코드 가이드에 있습니다.

2. 네이버 계정

서로이웃을 걸 계정입니다. 처음 돌릴 때는 부계정을 권합니다.

브라우저 자동화 도구(Playwright)는 Claude가 알아서 깔아줍니다. 따로 준비할 게 없습니다.

BUILD

만들기 , 이 프롬프트 하나

폴더 하나 만들고 그 안에서 claude 를 켠 다음, 아래를 통째로 붙여넣으세요.

복붙용 프롬프트
네이버 블로그 서로이웃 신청 자동화를 만들어줘. neighbor_both.js 하나로.

【핵심 설계】
네이버는 신청 단계를 호출해야 하루 한도가 깎인다.
그러니 한도를 안 쓰는 조회로 먼저 걸러내고, 통과한 곳에만 신청한다.

【1단계 후보 수집】
m.search.naver.com 블로그 탭에서 아래 키워드로 검색해 블로그 아이디를 모은다.
  "서이추 환영 AI", "서로이웃 환영 자동화", "클로드 코드 자동화", "AI 블로그 자동화"
페이지 이동 사이에 1.4~2.4초 랜덤 대기.

【2단계 RSS 필터 , 한도 안 씀】
각 후보의 블로그 RSS를 읽어 세 가지를 본다.
  1) 최근 글이 14일 안에 있나 (없으면 휴면으로 제외)
  2) 협찬·체험단 같은 광고 문구가 있나 (있으면 제외)
  3) 최근 글 제목에 내 주제어가 2편 이상 나오나
     주제어: 클로드|Claude|바이브코딩|노코드|자동화|프롬프트|n8n|메이크닷컴
     제목 2편이 안 되면, 본문에 강신호 5회 + 약신호 2회여도 통과시킨다.

【3단계 사전확인 , 한도 안 씀】
BuddyAdd 폼이 열리는지만 확인한다. 확인 버튼은 누르지 않는다.
여기까지 통과한 곳만 4단계로 넘긴다.

【4단계 신청 , 여기서 한도 씀】
RSS에서 가져온 최근 글 제목 3편 + 본문 발췌 400자를 너에게 주면
그 사람이 실제로 다룬 것 하나를 짚어 한 문장을 지어라.
  예: "OO로 △△하는 편 잘 봤어요, 저는 □□ 쪽 기록 중인데 서로이웃 신청드려요"
제목을 따옴표로 그대로 옮기는 건 금지. 복붙 티가 나서 안 받아준다.
신청과 신청 사이에 12~25초 랜덤 대기. 사람 속도로.

【실행 모드 3개】
  node neighbor_both.js --check     세션 상태만 검사
  node neighbor_both.js             후보 발굴 + 사전확인까지 (한도 0)
  node neighbor_both.js --go 3      실제 신청 3건

【기록】
out/both_buddy.json 에 누가·언제·무슨 메시지로 나갔는지 남긴다.
같은 블로그에 두 번 걸지 않게 이 파일을 먼저 읽고 거른다.

로그인은 내가 직접 할 테니, 처음 한 번 브라우저를 띄워주고
로그인 끝나면 세션을 저장해서 다음부터 재사용해라.
왜 이렇게 길게 쓰나? 짧게 시키면 Claude가 "일단 많이 거는" 흔한 방식으로 만듭니다. 한도를 아끼는 순서와 대기 시간을 명시해야 그대로 만들어줍니다.
RUN

돌리는 건 명령 세 개

브라우저가 뜨면 직접 로그인하세요. 한 번만 하면 세션이 저장돼 다음부터는 안 물어봅니다.

평소 , 한도 안 쓰고 후보만 보기

발굴만
node neighbor_both.js

여기까지는 신청이 안 나갑니다. 어떤 블로그가 걸러졌는지 이유까지 다 찍힙니다. 마음 편히 여러 번 돌려도 됩니다.

실제로 걸 때

신청 3건
node neighbor_both.js --go 3
숫자를 크게 넣지 마세요. 처음엔 3으로 시작해서 며칠 지켜보고 늘리세요. 한 번에 수십 건은 계정에 좋을 게 없습니다.
MESSAGE

메시지가 갈림길입니다

필터를 아무리 잘 짜도, 마지막에 보내는 문장이 복붙이면 안 받아줍니다. 받는 사람은 바로 압니다.

안 받아주는 쪽받아주는 쪽
재료검색에 걸린 글 제목 하나최근 글 제목 3편 + 본문 발췌
문장"OOO" 잘 봤습니다그 사람이 다룬 것 하나를 짚음
티누구한테나 보낸 티읽고 쓴 티
실제로 나간 메시지입니다.
"힉스필드로 무료 시네마틱 영상 뽑는 편 잘 봤어요, 저는 비개발자용 AI 자동화 쪽 기록 중인데 서로이웃 신청드려요"

재밌는 건, 검색에 걸린 그 블로그의 글은 클로드 리뷰였다는 점입니다. 힉스필드 편은 검색에 안 걸린 다른 글이었어요. 걸린 글 하나만 보는 게 아니라 그 블로그의 최근 글들을 같이 읽기 때문에 이런 문장이 나옵니다.

TRAPS

실전 함정 5가지

1. 신청부터 걸면 한도가 녹습니다

휴면 블로그에 걸어도 한도는 똑같이 깎입니다. 사전확인 단계를 빼먹지 마세요. 이 자동화의 존재 이유가 그 단계입니다.

2. 제목만 보고 니치를 판단하면 헛짚습니다

제목에 "AI"가 한 번 들어갔다고 AI 블로그가 아닙니다. 그래서 제목 2편 이상을 조건으로 걸었습니다. 한 번 언급은 통과 못 합니다.

3. 대기 시간을 줄이면 계정이 위험합니다

신청 사이 12~25초는 안전장치입니다. 속도가 답답해도 줄이지 마세요. 병렬로 여러 개를 동시에 거는 것도 금지입니다.

4. 같은 블로그에 두 번 걸립니다

기록 파일을 안 만들면 어제 건 데를 오늘 또 겁니다. out/both_buddy.json 을 먼저 읽고 거르게 하세요.

5. 본문 읽기가 실패하면 조용히 제목 복붙으로 내려갑니다

제가 실제로 겪은 겁니다. 예비 경로를 만들어두면 편한데, 그게 하필 하지 말라던 방식이었어요. 기록 파일을 가끔 열어서 어떤 문장이 나갔는지 직접 확인하세요.

SAFE

안전하게 오래 쓰는 법

  • 처음엔 --go 3 으로 시작. 며칠 지켜보고 천천히 늘립니다.
  • 부계정으로 먼저 돌려보고, 괜찮으면 본계정으로 옮깁니다.
  • 대기 시간은 절대 줄이지 않습니다. 이게 유일한 안전장치입니다.
  • 기록 파일을 주에 한 번은 열어봅니다. 이상한 문장이 나가고 있는지 눈으로 확인합니다.
  • 수락률이 낮으면 신청 수를 늘리지 말고 메시지를 고치세요. 갈림길은 거기입니다.
