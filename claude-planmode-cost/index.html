어디서 시작된 얘기냐면

"플랜 모드를 켜면 비용이 훨씬 든다"는 말이 많아서 직접 재 봤습니다. 같은 요청을 플랜 모드 없이 3번, 플랜 모드로(계획을 받고 승인한 뒤 진행) 3번 만들게 했어요.

※ 실험은 2026-10-10, 모델 Opus 5.5(claude-opus-5-5), effort high, claude -p 로 돌렸습니다. 금액은 실제 청구액이 아니라 API 정가로 환산한 값이에요. 제가 잰 요청 하나, 3번씩의 결과라서 모든 작업에 그대로 들어맞는다는 뜻은 아닙니다.

플랜 모드 쪽 비용을 쪼개 보면

플랜 모드 3번 평균 $1.83 = 1단계 $1.03 + 2단계 $0.80

1단계 $1.03 을 "계획 비용"이라고 읽으면 틀려요

1단계 비용의 큰 몫은 세션을 시작할 때 읽는 기본 내용을 처음 저장하는 비용이고, 바로 시키기도 같은 비용을 냅니다. 그래서 실제로 플랜 모드가 더 쓴 건 합계 차이 약 $0.21 입니다.

한 대화로 이어 가서 덜 오른 걸로 보여요 (추정)

플랜 모드 2단계에서 캐시에서 다시 읽은 입력이 약 23만 토큰, 새로 캐시에 올린 입력이 2만~3만 토큰이었어요(3번 모두). 계획과 구현을 따로 호출해 이어받는 옛 방식에서는 캐시를 약 24만 토큰 다시 만들었고 비용이 $3.5 안팎까지 불었습니다(이 방식은 영상에 쓰지 않았어요). 원인을 단정할 수는 없고, 3번 실험이라 "보인다" 정도로만 말합니다.

⚠️ 한계: 조건이 완전히 같지 않았어요

바로 시키기와 플랜 모드는 번갈아 돌리지 않고 시간대를 나눠 돌렸고(바로 시키기 00:06~01:20, 플랜 모드 08:12~08:27), Claude Code 버전이 달랐고(2.1.295 / 2.1.296), 실행마다 로드된 도구(MCP) 수가 달랐습니다. 범위도 겹쳐요: 바로 시키기 $1.52~1.78, 플랜 모드 $1.77~1.94. 그래서 1.1배는 오차 범위일 수 있습니다. 같은 버전·같은 도구 구성으로 번갈아 다시 재면 이 글에 결과를 추가할게요.

직접 해 보세요

  1. 새 대화에서 시프트 탭을 눌러 플랜 모드를 켜고(입력창 아래에 plan mode on이 보여요) 아래 요청문을 보냅니다. 계획이 나오면 승인해서 같은 대화에서 끝까지 진행하세요.
  2. 또 새 대화에서 플랜 모드를 끄고 같은 요청문을 보냅니다.
  3. /usage 로 비교하세요. 구독이면 달러가 아니라 사용량 퍼센트가 나옵니다. API 계정이라면 /cost 로 달러를 봅니다.
  4. 한 번의 차이는 작을 수 있어요. 여러 번 돌려 보세요.
