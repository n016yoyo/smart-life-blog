한 줄 요약

9월 28일에 effort 단계별로 한 번씩 재 둔 호랑이 요청 기록이 있어서, 같은 클라이언트와 같은 요청으로 다시 돌렸습니다. 커넥터를 켜 둔 판에서는 low·medium 의 처음 값이 다시 잰 폭 안이었고, high 는 세 번 다 처음보다 짧았고, xhigh 는 두 번 다 길었습니다. 커넥터를 끄고 한 번 더 재니 low 는 다섯 번 다 처음보다 짧았고, high 는 174초에서 414초까지 벌어져 처음 값이 그 폭 안이었고, xhigh 는 이번에도 두 번 다 처음보다 길었습니다.

처음 기록이 단계당 한 번뿐이라, 그 한 번이 평소 값인지 튄 값인지 가릴 수 없습니다. 그래서 이 시간 값으로는 너프라고도 아니라고도 말하지 않습니다.

횟수는 low·medium 5번, high 3번, xhigh 2번씩입니다(xhigh 는 한 번에 15~26분이라 두 번만 돌렸습니다). 「폭」은 같은 단계를 여러 번 돌린 값의 가장 작은 값과 가장 큰 값, 「처음 값이 안/밖」은 9월 28일 한 번 값이 그 폭 안에 있는지입니다. 서른 번 모두 결과 파일이 콘솔 오류 없이 재생됐습니다(헤드리스 크롬에서 16초 재생).

두 판의 차이

커넥터 켬 판은 처음 기록과 같은 플래그(--setting-sources "" --tools "Read,Write,Edit")로 돌렸고, 세션이 클로드 앱 커넥터 세 개를 달고 시작했습니다(실행 기록의 mcp 서버 3개, 연결 상태는 실행마다 달라 Claude Docs 만 연결되거나 셋 다 대기 중이기도 했습니다). 커넥터 끔 판은 거기에 --strict-mcp-config 만 더했습니다(mcp 0개). 처음 기록(9월 28일)의 실행 기록에는 커넥터가 0개로 찍혀 있지만, 비용 구조(캐시 쓰기 약 8만 토큰)는 커넥터 켬 판과 같았습니다. 처음 기록이 어느 쪽과 같은 조건이었는지는 확정하지 못했습니다.

두 판은 커넥터 말고 돌린 시각도 다릅니다(켠 판은 한국 시간 오전, 끈 판은 낮). 시각이 시간에 준 영향은 가리지 못했습니다.

비용도 달랐습니다. 빈 폴더에서 low 한 번의 정가 환산이 커넥터 켬 판에서는 $0.70~$0.78(캐시 쓰기 약 7만 7천 토큰), 0개 판에서는 $0.125~$0.138(캐시 쓰기 약 6천 토큰)이었습니다. 왜 그런지는 가려내지 못했습니다.

직접 재는 법, 셋

제 값과 같은 방식으로, 빈 폴더에서

1

요청, 클로드 코드 버전, 커넥터를 고정

위 요청문을 request.txt 로 저장하고, 아래 스크립트처럼 버전(npx 로 2.1.280)과 커넥터(--strict-mcp-config)를 정해 돌립니다. 둘 중 하나가 바뀌면 같은 요청도 값이나 비용이 달라질 수 있습니다.

2

같은 단계를 다섯 번 돌려서 폭을 보기

한 번 값은 평소 값인지 튄 값인지 알 수 없습니다. 다섯 번 돌려 가장 작은 값과 가장 큰 값을 적습니다. 저는 high 는 세 번, xhigh 는 한 번에 15~26분이라 두 번이었습니다.

3

처음 값이 그 폭 밖이어도 단정하지 않고 한 번 더

비교하려는 처음 값이 다시 잰 폭 안이면 같은 범위의 흔들림일 수 있습니다. 밖이어도 곧바로 바뀌었다고 하지 않고, 한 번 더 돌려 폭이 넓어지는지 봅니다.

measure.sh · 사용: ./measure.sh low 5
#!/bin/bash
# 직접 재는 스크립트(가이드용, 어디서든 돈다). 같은 요청을 같은 단계로 여러 번 돌려 걸린 시간·정가 환산 비용·출력 토큰을 표로 낸다.
#   사용: ./measure.sh <low|medium|high|xhigh> <횟수> [요청파일 request.txt]
#   ★클라이언트 버전을 고정한다(npx 로 2.1.280). 버전이 바뀌면 같은 요청도 값이 달라질 수 있어서다.
#   ★--strict-mcp-config 로 연결된 커넥터(MCP)를 끈다. 켜 둔 판과 끈 판의 값이 달랐다(저희 low 한 번에 캐시 쓰기 약 7만 7천 대 약 6천 토큰, 정가 환산 $0.70~$0.78 대 $0.125~$0.138 , 원인은 가리지 못했다). 재현하려면 끈 쪽으로 고정한다.
#   ★빈 폴더에서 돌린다(위쪽 폴더에 CLAUDE.md 같은 설정이 있으면 입력이 늘어 비용이 달라진다). 저희 저장소 폴더 안에서 같은 low 를 돌렸더니 $0.22 였다(원인은 확인하지 않았다).
#   ★한 번 돌릴 때마다 정가 환산 low 약 $0.13 · medium $0.25~$0.53 · high $0.50~$1.21 · xhigh $2.86~$3.51 어치가 든다(저희 값). 단계가 높을수록 오래 걸리고 폭도 크다(저희 xhigh 는 15분~26분).
LEVEL=${1:?단계 low|medium|high|xhigh}; N=${2:?횟수}; REQ=${3:-request.txt}
[ -f "$REQ" ] || { echo "요청 파일이 없다: $REQ"; exit 1; }
CC="npx --yes @anthropic-ai/claude-code@2.1.280"
OUT="measure_$LEVEL"; mkdir -p "$OUT"
for i in $(seq 1 "$N"); do
  D="$OUT/run_$i"; mkdir -p "$D"; cp "$REQ" "$D/request.txt"
  ( cd "$D" && $CC -p --model claude-opus-5-5 --effort "$LEVEL" --setting-sources "" --tools "Read,Write,Edit" --strict-mcp-config \
      --permission-mode acceptEdits --output-format stream-json --verbose "$(cat request.txt)" > stream.jsonl 2> stderr.txt )
  node -e '
    const fs = require("fs"); let r = null;
    for (const l of fs.readFileSync(process.argv[1] + "/stream.jsonl", "utf8").split("\n")) { try { const j = JSON.parse(l); if (j.type === "result") r = j; } catch {} }
    console.log(process.argv[2].padEnd(8), "run " + process.argv[3], (r.duration_ms / 1000).toFixed(1).padStart(7) + "초", "$" + r.total_cost_usd.toFixed(4), "출력토큰 " + r.usage.output_tokens);
  ' "$D" "$LEVEL" "$i"
done

이 스크립트를 빈 폴더(저장소 밖)에서 low 로 한 번 돌려 확인했습니다: 49.6초, 정가 환산 $0.1462(캐시 쓰기 6,176 토큰). 같은 설정으로 잰 커넥터 끔 판의 low 폭(33~38초) 밖의 값이라, 한 번 값으로 판단하지 말고 다섯 번 돌려 폭을 보라는 이유가 그대로 드러났습니다. 한 번 돌릴 때마다 정가 환산 비용이 듭니다(제 값: low 약 $0.13 · medium $0.25~$0.53 · high $0.50~$1.21 · xhigh $2.86~$3.51). 구독이면 청구되지 않고 한도에서 나가며, 이 실험이 한도를 몇 % 썼는지는 재지 않았습니다. 저희 저장소 폴더 안에서 같은 low 를 돌렸더니 $0.22 가 나왔으니, 위쪽 폴더에 CLAUDE.md 같은 설정이 없는 빈 폴더에서 돌리세요.

알아 둘 것

제가 잰 건 요청 한 종류, effort 네 단계(low·medium·high·xhigh), 시간입니다. 9월 28일 기록에 있던 max(1시간 16분)는 한 번에 걸리는 시간 때문에 이번엔 다시 재지 않았습니다. 모델 전체가 느려졌는지 빨라졌는지는 이 실험으로 말할 수 없습니다.

서버 쪽에서 무엇이 바뀌었는지는 모릅니다. 제가 아는 건 같은 요청의 값이 어떻게 달랐는가뿐입니다.
