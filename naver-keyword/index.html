왜 해봤냐면

블로그 검색 첫 화면에 제 글이 떠 있었습니다. 순위 감시기까지 만들어 매일 확인하고 있었고요. 그런데 검색량을 한 번도 안 재봤습니다.

재보니까 그 키워드를 찾는 사람이 한 달에 열 명 남짓이었어요. 순위를 재던 키워드 6개를 전부 재봤더니 셋은 검색량이 아예 안 잡혔습니다. 3위까지 올라갔던 것도 그중 하나였고요.

원인은 단순했습니다. 제가 만든 앱 이름을 그대로 키워드로 썼거든요. 아무도 그 말로 검색하지 않는데 그 자리에서 순위를 올리고 있었던 겁니다.

※ 이 페이지는 클로드 코드(터미널에서 claude)를 쓰는 걸 전제로 씁니다. 코드는 제가 짜지 않고 프롬프트 한 문단으로 시켰습니다.

준비물은 키 두 개

둘 다 무료. 한 번만 받으면 됩니다

1

검색광고 API , 검색량

searchad.naver.com 로그인 → 광고주 가입(개인도 됩니다, 결제 정보 없이) → 우측 상단 도구 › API 사용 관리 → 서비스 신청.

화면에 액세스라이선스·비밀키가 뜹니다. CUSTOMER_ID 는 광고시스템 우측 상단 계정 옆 숫자예요.

광고를 돌리지 않아도 됩니다. 가입만 하면 API 는 무료입니다.

2

검색 API , 문서수

developers.naver.com/apps → 애플리케이션 등록 → 사용 API 에 검색 체크 → 환경은 WEB(주소는 아무거나).

Client ID·Client Secret 이 바로 나옵니다. 하루 25,000회까지 무료입니다.

"네이버 로그인" 항목이 개발 중으로 같이 떠도 검색 API 는 바로 됩니다. 저도 그 상태로 됐어요.

키는 화면에 찍지 마세요

키를 대화창에 붙여넣지 말고 파일에 저장한 뒤 파일 경로만 알려주세요. 아래 프롬프트가 그렇게 돼 있습니다. 녹화·스크린샷을 할 일이 있으면 특히요.

제가 친 프롬프트 원문

토씨 하나 안 고쳤습니다

프롬프트 (그대로 붙여넣기)
네이버 검색광고 API(keywordstool)로 키워드의 월간 PC·모바일 검색량을 가져오고, 네이버 검색 API(blog.json)의 total 로 블로그 문서수를 가져와서, 문서수 ÷ 검색량 을 비율로 계산해 낮은 순으로 표를 찍고 CSV 로 저장하는 스크립트를 만들어줘. 키는 .naver_searchad.json 과 .naver_openapi.json 에 있어. 값은 절대 출력하지 마. 검색광고 API 서명은 HMAC-SHA256(비밀키, 타임스탬프.GET.경로) 를 base64 로.

돌리는 순서

  1. 빈 폴더를 만듭니다
  2. 그 안에 키 파일 두 개를 만듭니다
    .naver_searchad.json → {"customerId":"숫자","apiKey":"액세스라이선스","secretKey":"비밀키"}
    .naver_openapi.json → {"clientId":"...","clientSecret":"..."}
  3. 그 폴더에서 claude 를 켜고 위 프롬프트를 붙여넣습니다
  4. 다 되면 궁금한 키워드를 이어서 시킵니다 , 기프티콘관리앱 재입고알림 냉장고재고앱 재줘
  5. 표가 나오고 out/ 폴더에 CSV 가 쌓입니다

저는 이렇게 씁니다

숫자 두 개면 끝납니다

1

쓸 키워드를 죽 적어 넣는다

고민하지 말고 떠오르는 대로 스무 개쯤. 한 번에 다 잽니다.

2

글 수를 사람 수로 나눈다

문서수 ÷ 검색량. 이 값 하나만 봅니다.

3

10 넘으면 버리고, 남은 말로 제목을 잡는다

10이라는 선은 제가 정한 것입니다. 잰 값이 아니라 판단이라, 재보시고 본인 선을 잡으셔도 됩니다. 저는 남은 키워드로 글 제목을 잡고, 순위 추적도 그것만 합니다.

이 숫자로 하면 안 되는 것

순위 예측에 쓰지 마세요. 문서수는 그 말로 네이버 블로그를 검색했을 때 나오는 전체 결과 수입니다. 그 말이 든 글을 넓게 세기 때문에, 띄어쓰기 없는 합성어일수록 크게 잡힙니다. 제 실측에서 "블로그자동화"는 문서수가 536만으로 나왔어요.

그래서 저는 후보를 거를 때만 씁니다. 열 개 중 세 개로 줄이는 용도지, 그 세 개의 순위를 매기는 용도가 아닙니다.

검색량 = 네이버 검색광고가 주는 최근 한 달 월간 조회수(PC+모바일). 우리가 계산하지 않고 받은 값 그대로입니다.

문서수 = 그 말로 네이버 블로그를 검색했을 때 나오는 전체 결과 수입니다. 그 키워드만 정확히 담은 글 수가 아닙니다.

비율 = 문서수 ÷ 검색량. 유료 툴의 "경쟁도"와 같은 식이지만, 툴 이름이 붙은 지수를 흉내내지 않고 이 식 하나만 씁니다.
이 페이지 숫자의 출처 , 전부 2026년 9월 7일 한 번의 실행에서 제 화면에 찍힌 값입니다. 검색량은 네이버 검색광고 API keywordstool, 문서수는 네이버 검색 API blog.json 의 total 이고, 비율은 그 둘을 나눈 값입니다. 순위는 제 순위 감시기가 2026년 8월 11일부터 기록한 값이고, 네이버 블로그 탭 검색 결과 안에서 제 글의 위치입니다. 검색량·문서수·순위는 매일 바뀌므로 직접 재보시면 값이 다를 수 있습니다. 비율 10 이라는 기준은 잰 값이 아니라 제가 정한 선입니다.
